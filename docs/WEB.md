# 1. 本机 Web 实验室

前端使用 React、TypeScript、Vite，React Router 管理页面路由，TanStack Query 管理请求缓存，ECharts 绘制多实验对比图。后端使用 FastAPI、SQLite 和独立工作进程，通过 REST API 与 SSE 实时事件连接前端；训练、推理和报告复用 `clsframework.Classifier`，原有 CLI 和 Python API 继续可用。

## 1.1 首次安装

在项目根目录执行，需要 Node.js 22.12+（本机验收使用 22.23.2）和 uv：

```powershell
uv sync --extra web
cd web
npm ci
cd ..
```

需要同时保留 ONNX 导出依赖时，改用 `uv sync --extra web --extra export`。

## 1.2 一条命令启动

```powershell
uv run --extra web scripts/web.py
```

脚本启动前后端并自动打开浏览器：<http://127.0.0.1:5173>。API 文档位于 <http://127.0.0.1:8000/docs>。不希望自动打开浏览器时加 `--no-browser`。

保留这个终端；按 Ctrl+C 停止本次启动的前后端和 Web 工作进程。**关闭浏览器页面不会停止训练，关闭后端会停止活动任务。** 未开始的排队任务保留，下次启动后继续调度；上次意外中断的活动任务标记为“已中断”，不会声称已经完成，也不会自动重新提交。

## 1.3 分别启动前后端

终端一，在项目根目录：

```powershell
uv run --extra web cls-web
```

终端二：

```powershell
cd web
npm run dev
```

前端通过 Vite 把 `/api` 代理到 `127.0.0.1:8000`。端口占用时直接报错，避免自动换端口导致跨域配置失效。后端提供 `--workspace` 和 `--port` 参数；自定义后端端口时，在前端进程设置环境变量 `CLS_API_URL`（例如 `http://127.0.0.1:8051`）。自定义前端端口时，在后端进程设置 `CLS_WEB_PORT`，并向 Vite 传入对应的 `--port`。默认只绑定本机，不提供账号、多用户隔离或公网部署。

# 2. 页面操作

## 2.1 训练工作台

1. 从 8 个网络模型中选择模型，默认 ResNet18。
2. 选择 `data/` 下的数据集，默认 `flower_photos_split`。页面显示类别和 train/val/test 图片数量。
3. 设置训练轮数、batch、初始权重和设备。展开高级参数可以修改学习率、workers、seed、微调方式和离线模式。
4. 点击“开始训练”，任务进入后台调度。训练默认不按任务数量限流，推理并发 1、评估与报告并发 1。GPU 显存达到启动阈值即可共享显卡；同名实验锁和内存保护仍生效。

Web 表单默认“跟随全局设置”，在设置页配置 CPU、自动选择、GPU，以及使用的物理显卡。全局初始值为自动选择单卡：服务器 CUDA 与 GPU 监控可用时使用 GPU，否则使用 CPU。勾选一张卡固定使用该卡；勾选多张卡表示同一训练任务使用这些卡进行 DDP 训练，仅支持 Linux CUDA。明确指定 GPU 时不可用即报错，显存或并发额度不足时排队，不回退到 CPU。训练页也可以为本次任务覆盖全局设置。其余默认参数为每卡 batch=4、workers=0、CPU 线程数 2、10 轮。多卡有效 batch 还需乘以显卡数及梯度累积步数。输入尺寸、归一化和分类头由原框架适配，初始预训练权重缓存到 `weights/`，缺失时按配置下载。离线模式缺缓存会明确失败。

“接着上次权重微调”明确使用仅继承参数的语义，可调整轮数和学习率，创建新实验；“从官方预训练权重开始”不继承历史训练参数。Web 的这两个选项不进行严格断点恢复。需要严格恢复原运行时使用 CLI `--resume`，相关契约仍由核心框架校验。

提交时固定所选历史 checkpoint，排除仍在运行的训练目录；等待期间不会自动改用其他任务新写入的权重。没有可用历史权重时使用配置中的官方初始化。相同实验名的训练依次执行，以满足核心框架的实验锁约束；高级参数可填写不同的“实验名称”（字母开头或数字开头，允许字母、数字、下划线、短横线，最多 64 字符），并行比较同一模型的参数。新名称拥有独立的历史权重记录。

1 轮训练自动将 warmup 调整为 0；其余轮数取公共配置 warmup 与 `epochs - 1` 的较小值。最低学习率限制为不超过本次学习率。Web 不使用 smoke 或数据截断。

## 2.2 数据准备

花卉数据首次使用前运行：

```powershell
uv run scripts/prepare_flowers.py
```

完成后点击数据选择区域的刷新按钮。也可以自行准备：

```text
data/my_dataset/
  train/
    class_a/*.jpg
    class_b/*.jpg
  val/
    class_a/*.jpg
    class_b/*.jpg
  test/                  可选；独立测试需要此目录
    class_a/*.jpg
    class_b/*.jpg
```

目录扫描仅统计文件，训练工作进程仍会执行核心框架的数据完整性检查。Web 开启图片验证缓存：每次仍计算每张图片的 SHA256、检查类别映射和跨 split 泄漏，只有内容已验证且 Pillow 版本相同的图片跳过重复解码。文件内容改变或缓存损坏时重新解码，数据指纹与关闭缓存时一致。缓存位于 `cache/image_validation/`，只保存内容哈希，不复制图片或权重。CLI 可设置 `runtime.cache_image_validation=true`，仅支持 strict 完整性检查的 ImageFolder/manifest，其他组合明确拒绝。更换为模型配置原路径之外的数据集时，Web 给实验名追加数据集名称，避免自动接着另一数据集的权重训练。相同路径下更改类别也会由核心框架拒绝不匹配权重。

当前 Web 提供 ImageFolder 的可视化配置，模型列表来自 `configs/flower/flower_*.yaml`（排除 `flower_base`）。增加新的兼容模型配置后重启后端；无效配置和插件配置不会静默忽略。

## 2.3 任务与日志

侧栏“设置”是独立的全局配置页面，训练和推理页面不再放置并发编辑面板。训练设备、并发、外观和刷新配置统一保存在 `configs/web.yaml`，点击“保存全局设置”后立即生效。设备配置对新提交任务生效，已排队或运行的任务保留提交时的设备快照；复制任务也保留原设备。编辑排队任务执行参数时会按当前全局设置重新解析。推理与独立评估仍使用 CPU。

```yaml
training:
  device: auto  # auto / cpu / gpu
  gpu_indices: [] # [] 自动单卡；[6] 指定单卡；[6, 7] 同一任务双卡 DDP
concurrency:
  train: 0      # 0 不限制训练任务数量；1～8 设置数量上限
  predict: 1    # 推理进程数：1～8
  auxiliary: 1  # 验证、测试、报告共享额度：1～4
inference:
  resident: true   # 复用推理进程；false 每任务启动独立进程
  cpu_threads: 2   # 1～32
  batch_size: 8    # 1～64
  cache_models: 1  # 每个进程 1～4 个模型
  cache_mb: 256    # 每个进程缓存参数与缓冲区上限，16～2048 MB
  idle_seconds: 300 # 空闲进程保留 30～3600 秒
appearance:
  theme: cyber # cyber / forest / ocean / violet / amber
  mode: dark   # light / dark / system
refresh_interval_seconds: 3 # 1～30 秒
resources:
  enabled: true            # 新任务启动前检查资源；不终止正在运行的任务
  max_memory_percent: 90   # 整机内存达到此百分比时暂停启动
  min_available_gb: 2      # 启动后预期至少保留的可用内存
  launch_reserve_gb: 1     # 每个新进程的启动预留内存；保留 15 秒
  min_gpu_free_gb: 2       # GPU 训练启动前所需空闲显存
  max_jobs_per_gpu: 0      # 0 不限任务数，仅按显存；1～8 设置每卡上限
```

将 `concurrency.train` 和 `resources.max_jobs_per_gpu` 都设为 `0`，即可取消训练总数与每卡任务数限制；已有 GPU 任务不会独占该卡的调度额度，显存达到启动阈值即可并行。`min_gpu_free_gb` 是启动时的空闲显存门槛，并非模型峰值显存预测；实际占用取决于模型、每卡 batch 和输入尺寸。系统内存保护和同名实验锁仍会让不满足条件的任务等待。也可设置 `concurrency.train: 8` 等正数恢复数量上限。推理进程按需启动，空闲时保留模型，超时或降低并发后释放多余空闲进程。取消一个推理任务只终止其进程，下一任务自动重建；关闭后端会释放全部推理进程。

默认使用深色“科技渐变”主题：深蓝背景、青蓝高亮、蓝紫渐变按钮和面板边框。另提供森林绿、海洋蓝、鸢尾紫、琥珀橙，所有主题支持浅色、深色和跟随系统。保存后所有页面及其他浏览器标签在下次刷新状态时同步，重启后保留。“恢复默认值”先填写默认值，点击保存才正式应用。旧版平铺的 train/predict/auxiliary YAML 会兼容读取并保留自定义额度，保存时写为上述结构。

五种主题均采用科技感渐变。森林绿为青绿与青蓝，海洋蓝为冰蓝与电蓝，鸢尾紫为星云紫与粉色，琥珀橙为金橙与珊瑚色；背景、侧栏、主按钮、面板边框、视图选中态和概率条统一随主题变化。浅色模式使用较深的文字与按钮色，深色模式使用对应色系的深色底与明亮高亮色。

底部固定状态栏显示服务连接、训练/推理/评估的运行数与上限、排队任务总数、整机 CPU 与内存占用、最近服务采样时间，并提供设置入口。状态栏不遮挡页面末尾的操作按钮。断连时显示“服务未连接”及缺省符号，不把旧指标当作当前值。CPU/内存是整机数据，不是某一个训练任务的独占用量。

增加上限会调度等待中的任务；降低上限不会杀死现有任务，而是在其完成后按新上限补充。满足资源与并发约束的任务按优先级从高到低启动，同优先级按提交顺序调度；同名实验被占用时跳过该任务，让其他实验先运行。训练高级参数可以设置优先级（0～10）和运行时限（分钟，0 不限时）；排队任务也可在编辑窗口修改。运行时限从任务实际启动计算，不计排队时间，超时只停止该任务并标记失败。API 本身仍使用单个 Uvicorn 进程，不应通过增加 Uvicorn workers 实现训练并行。

设置页集中配置内存与 GPU 资源保护。资源不足时任务保持排队并显示原因，不会静默改用 CPU。GPU 训练可指定物理卡或自动选择满足条件的卡，工作进程通过 `CUDA_VISIBLE_DEVICES` 绑定该卡；其他进程的显存占用也会影响可启动条件。关闭资源保护会跳过内存与显存阈值检查，但仍保留每卡任务数限制。资源采样和启动预留是估算，不能保证模型峰值内存始终充足。

任务状态包含排队、运行、完成、失败、取消、中断。SSE 按全局刷新间隔（默认 3 秒）推送状态及所选任务的日志增量；队列变化会使列表缓存失效。断线时自动恢复 REST 轮询，连接恢复后获取当前快照和最近 48 KB 日志，不重放所有历史事件。完整日志保存在磁盘。列表另有低频刷新，用于恢复漏掉的更新。

训练进度按实际完成的验证轮次更新。首轮前可能在检查数据、下载权重或训练，页面不会伪造批次进度。准确率曲线来自 `metrics.jsonl`；没有指标时显示空状态。

“停止任务”只终止该 Web 任务的子进程树，不停止从其他终端启动的训练。新任务的配置会保存为快照，服务重启后历史任务仍可查看。

任务管理支持表格、卡片、状态看板三种视图，并记住当前浏览器的选择。可按名称、ID、实验目录搜索，按类型与状态筛选，按时间或名称排序。搜索、筛选与分页由后端 SQLite 查询完成，表格和卡片每页 12 项，看板显示筛选后的前 200 项；列表响应不携带完整预测结果。

- **新建与查看**：任务管理页只显示列表和管理操作。新建入口通往训练、推理或实验评估表单；点击任务名称或查看按钮，进入独立“任务结果”页查看进度、指标和日志。结果页可切换任务或返回任务管理。
- **编辑**：所有状态均可改名；只有排队任务允许修改执行参数。保存前若已被调度，接口拒绝参数修改。改名不改变排队顺序，修改优先级会影响后续调度。
- **复制并运行**：按原配置立即提交新任务。训练副本使用新的输出目录，并沿用原任务固定的初始化权重。
- **删除与批量删除**：可跨页选择，单批最多 200 项；确认后取消排队任务、停止选中的运行任务并删除记录，不影响其他任务。权重、实验目录、配置快照、上传图片、报告和日志均保留，实验结果页仍可访问已有模型。此操作不用于释放磁盘空间。

## 2.4 实验结果

自动发现 `runs/<实验名>/<运行编号>/checkpoints/best.pt`，并兼容旧 bundle 目录，支持查看已存在的 CLI 与 Web 训练结果。训练曲线、逐类指标、混淆矩阵和 HTML 报告可直接打开。

“实验对比”最多选择 4 个实验，支持交互式验证准确率曲线、缩放、图例切换、最高/最后记录轮指标，以及配置快照的参数差异表。选择保存在页面 URL，刷新后保留。缺失指标显示空值，不补零；不同数据集或划分的实验不宜直接按准确率排名。图表模块按需加载，主题随全局设置变化。

旧实验没有图表时，点击“重新生成报告”，成功后回到实验结果页即可查看。此操作读取已有指标，不重新训练。训练报告中的混淆矩阵对应最后记录轮；点击“验证集评估”或“测试集评估”才能得到保存的最佳模型的独立评估结果，报告在相应任务详情中打开。

## 2.5 图片推理

选择已完成训练的模型，拖入图片或点击上传，再点击“开始推理”。每次最多 20 张图片，单张最多 20 MB、2000 万像素。图片解码后规范化为 RGB PNG；文件名不会被直接用作服务器路径。

切换页面后会保留当前已选图片。点击“清空图片”可一次清除当前选择，再点击上传区域重新选择，包括刚刚清除的同一张图片；清空后不能提交推理，直到重新选择图片。该操作不会删除历史任务及其图片结果。

推理页面不再提供保存开关，统一只推理，仅长期保留类别、概率、原文件名、任务记录和日志；上传及推理过程中使用临时磁盘文件，任务完成、失败、取消或中断后清理，不生成标注图和 HTML 报告。结果页仍可通过当前浏览器会话临时预览本次图片，显示实际临时推理路径并标注文件已清理，详细、卡片和表格视图均支持。为限制内存使用，只保留最近一次推理的预览，新任务会释放旧预览；刷新或关闭页面后预览不可恢复。再次推理或复制已清理任务时需要重新上传。其他排队、运行中或选择保存的任务仍引用同一上传图片时，不删除共享文件；旧版历史图片不自动清理。尚未提交任务的上传不属于任务结束清理范围。

提交后进入独立“任务结果”页面，每张图片以左右布局显示：左侧为未标注的输入图片、原文件名和实际文件路径，右侧为预测类别、概率及类别概率条。手机端改为上下排列。多张图片按上传 ID 匹配结果，避免目录排序导致错配。点击输入图片可打开大图。页面提交固定使用 `save_images: false`，不再读取旧浏览器的保存偏好。底层 API 保留 `save_images` 参数以兼容已有调用；历史已保存任务的图片和报告仍可查看。

图片路径是本机服务保存的 RGB PNG 位置：执行前位于 `runs/web/uploads/`，执行后优先显示该任务 `inputs/` 中的快照。浏览器不提供上传前的完整磁盘路径，所以不会显示虚构的源路径。原文件名独立保存，刷新或服务重启后仍可显示；旧上传记录没有文件名信息时显示保存的文件名。

任务页地址为 `/#/jobs`，结果页为 `/#/results/<任务ID>`，支持直接访问、刷新及浏览器前进/后退；旧版 `/#results/<任务ID>` 链接会自动转换。概率是模型输出，不代表模型已经过概率校准。当前使用本地训练的 .pt，并兼容旧 bundle，不接受上传可执行模型或任意 checkpoint。

任务结果页支持三种视图：**详细**查看单个任务的图表、预测和日志；**卡片**与**表格**浏览全部任务结果，支持名称/ID/实验搜索、类型筛选及每页 12 项分页。点击“查看结果”进入该任务的详细视图。

推理详情内另有独立的图片视图切换：**详细**左右对照原图与概率；**卡片**网格浏览多图；**表格**紧凑显示缩略图、文件路径、类别和概率，可展开所有类别概率。任务视图与图片视图分别记忆在当前浏览器，刷新后保留；手机端卡片自动单列，表格在容器内横向滚动。

**推理不执行 epochs**：一次任务只对提交的图片进行预测。预测完成立即返回类别与概率；开启保存时，HTML 报告和标注图片通过辅助队列后台生成，报告失败单独显示，已有预测保持可用。内部报告任务不重复出现在任务列表，但占用评估与报告额度。任务耗时截止预测完成，报告耗时单独记录；历史训练曲线可在“实验结果”中查看。

缓存采用 LRU 淘汰，每次仍校验权重内容哈希和版本，权重或元数据变化后重新加载。缓存上限只统计模型参数与缓冲区，不包括 PyTorch、图片张量等额外内存；超过上限的模型完成当前预测后不留在缓存。图片快照优先使用硬链接，文件系统不支持时复制。

结果页显示排队、进程启动、运行库导入、权重校验、模型加载、预处理、前向计算和后台报告耗时。原始记录位于任务结果的 `timings`；训练 `events.jsonl` 新增每轮耗时和训练图片吞吐（耗时含本轮验证，吞吐按实际训练批次统计）。Web 训练结果还记录每 200 ms 采样的工作进程树 RSS 峰值，推理记录当前工作进程 RSS；这些信息单独保存，不写入 `.pt`。

| 接口 | 用途 |
|---|---|
| `GET /api/health` | 服务状态 |
| `GET /api/settings` | 全局配置（并发、推理缓存、资源保护、主题、刷新间隔） |

| `GET /api/status` | 全局配置、队列统计、整机 CPU/内存和采样时间 |
| `GET /api/scheduler` | 各类并发上限、运行数量、排队数量 |

| `POST /api/train` | 提交训练配置 |
| `GET /api/jobs` | 查看任务列表 |

| `GET /api/events` | SSE 状态流；job_id 可选，订阅单个任务详情与日志增量 |

# 4. 开发与验收

```powershell
# 后端：微型 CPU 训练/推理并行、独立限流、取消隔离、配置持久化、报告与输入校验
uv run --extra web python -m pytest web/qa -q

# 修改 Web 请求或设置模型后，重新生成契约
uv run --extra web scripts/export_web_schema.py

# 前端：类型检查和生产构建
cd web
npm run api:generate
npm run build

# 前后端启动后执行；默认使用本机 Microsoft Edge
npm run test:e2e
```

浏览器测试中的真实花卉推理依赖本机已准备的数据和模型。其他平台可设置 `PLAYWRIGHT_CHANNEL=chromium` 并执行 `npx playwright install chromium`。本次验收为 Windows CPU 环境，合成数据测试只验证工作流程，不能当作花卉准确率或所有网络收敛的认证。

全局设备设置有保存与重载、提交配置快照、显式 CPU 覆盖、无效设备拒绝、全卡资源预留、进程环境绑定、DDP 仅 rank 0 写结果的回归测试。浏览器验证覆盖显卡勾选、保存、刷新保留和训练继承全局设备；真实 CUDA 验收范围见 [GPU_SERVER.md](GPU_SERVER.md)。测试独立服务时可设置 `CLS_WEB_URL` 指定前端地址，避免触碰正在训练的工作区。

当前本机架构无需额外安装 Celery、Redis、MySQL 或 MinIO。扩展到多台工作机时，可用任务队列分发作业；多人协作时再考虑服务端数据库、身份与权限；跨机器访问权重和结果时再引入对象存储。上述分布式能力目前没有接入。

本功能放在独立 `clsweb` 包中。严格恢复使用核心源码摘要；如果同时修改 `src/clsframework`，旧 checkpoint 仍可能不满足严格恢复契约，使用匹配源码或改为仅加载参数微调。

接口与工具资料：[FastAPI 文件上传](https://fastapi.tiangolo.com/tutorial/request-files/)、[FastAPI CORS](https://fastapi.tiangolo.com/tutorial/cors/)、[Vite](https://vite.dev/guide/)、[React](https://react.dev/learn)。
